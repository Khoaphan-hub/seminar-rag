[Phan Anh Khoa · 75 seconds] Here is the pipeline, read from left to right, with a typical failure under each stage. We extract the PDF once, so any lost text or table layout affects everything later. Chunking can separate a condition from the claim it limits. An index can keep content that is out of date. Retrieval can miss the passage or return a related but wrong one. The prompt can lose metadata or be cut off. And generation can state more than the evidence supports. After retrieval, only the selected chunks reach the model, so it cannot look through the rest of the document. That is why we keep each chunk’s ID and page from the start. The last step is verification: every claim is checked against the passage it cites. A good pipeline does more than produce an answer. It preserves the path back to the evidence.
